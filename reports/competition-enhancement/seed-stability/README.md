# Поддержка метки МО при повторении оптимизации

В 20 заранее заданных повторных запусках **каждое из 2016 МО сохранило производственную метку во всех 20 запусках** после сопоставления групп по максимальному пересечению. Минимальная поддержка — 20/20; ARI каждого разбиения с исходным равен 1. Все 20 запусков сошлись к координатной неподвижной точке, за 4–8 проходов. Значение целевой функции во всех запусках — 0,484139557350085.

Это дополнительная проверка **устойчивости оптимизации** на одних и тех же данных 2023 года. Seed меняет инициализацию KMeans и порядок обхода вершин joint-оптимизатором. Признаки, граф, K и alpha остаются фиксированными. Частота 20/20 не является вероятностью экономической истинности типа, оценкой неопределённости из-за данных или постоянством метки по месяцам. Проверка не доказывает глобальную оптимальность и не заменяет существующие проверки бутстрепом месяцев, подвыборками МО и исключением регионов.

## Рецепт и регистрация

Рецепт совпадает с основной моделью в [validate_v12_findings.py](../../../scripts/validate_v12_findings.py): шесть атрибутов `health, marketplaces, horeca, food, transport, level`; X23 — медиана 12 стандартизованных месячных векторов 2023 года; K=4; детерминированный взвешенный kNN-граф, k=15, union; KMeans `n_init=50`; joint `alpha=0.5`, `max_sweeps=200`, ревизия `exact_centroid_moves_v2`. Исходные функции: [panel.py](../../../sbercluster/panel.py), [graph.py](../../../sbercluster/graph.py), [joint.py](../../../sbercluster/joint.py).

**Все seed 61001–61020 зарегистрированы до первого fit**, без подбора и замены: [registration.json](registration.json), создан 2026-10-09 01:07:10 UTC, SHA256 `681e549dc885fb766e999fe9a479c9c0d306ca982e87e63906a7f6a01750a779`. Сопоставление выполняется отдельно для каждого seed Hungarian-алгоритмом по 4×4 таблице пересечений с производственными метками. Детерминированные исходные метки и остальные scientific sources/inputs не изменены; их SHA закреплены в регистрации.

Первый seed занял 0,481 с; вместе с подготовкой прогноз 20 запусков составил 12,744 с. Полный расчёт разрешён правилом прогноза ≤600 с и завершён за 10,304 с: [timing.json](timing.json), [summary.json](summary.json). Единственный локальный тяжёлый слот; affinity `[0]`, один поток библиотек, BelowNormal, исходный Windows PDH guard CPU/RAM/GPU с порогом 95% и дисковым backoff. Две ресурсные выборки содержат валидные отдельные диски и GPU; ошибок нет: [resources.json](resources.json), [resource-monitor.jsonl](resource-monitor.jsonl). Процесс физически прочитал закреплённую панель 2023–2024 и обрезал её до 12 месяцев **до** масштабирования и графа; исходы 2024, выбор модели по 2024 и какие-либо данные 2025 не использовались.

## Таблицы и проверка

- [municipality_support.csv](municipality_support.csv): все 2016 МО, исходный тип, число согласий, `agreement_over_20`, счётчики попаданий в каждую из четырёх сопоставленных групп.
- [assignments.csv](assignments.csv): 2016 строк, исходные номера кластеров каждого из 20 запусков; [aligned_assignments.csv](aligned_assignments.csv): те же строки после сопоставления с производственными метками.
- [seed_metrics.csv](seed_metrics.csv): ARI, согласие, objective, convergence, проходы и время каждого seed; [fits.json](fits.json): таблицы пересечений, перестановки меток и полные монотонные трассы оптимизации.
- [group_summary.csv](group_summary.csv), [summary.json](summary.json): сводки каждой исходной группы и всех МО; [input_state.json](input_state.json), [features_2023.npy](features_2023.npy), [production_graph.npz](production_graph.npz): сохранённое пространство и граф для независимого пересчёта objective.
- [artifact_sha256.json](artifact_sha256.json): хеши сохранённых артефактов.

Из корня репозитория проверка сохранённых таблиц одной командой, без fit и записи файлов:

```console
python -B -m scripts.verify_seed_stability
```

Получен `PASS_READ_ONLY`: проверены хеши исходников и артефактов, все метки, максимум Hungarian также полным перебором 24 перестановок, ARI, целевые функции из X23/графа, трассы сходимости, поддержка каждого МО и обе сводки. Эта проверка выполнена автором скрипта; независимая инженерная приёмка проводится отдельно.

После расчёта исправлен **только общий portable guard**: он теперь учитывает измеренную долю занятой VRAM ≥95% и явно сохраняет неизвестные показания драйвера. Исторический seed-прогон использовал Windows-ветвь `ResourceMonitor` из `scripts/competition_synthetic.py`, а portable adapter не импортировал. Исходная регистрация не переписана: SHA256 `681e549dc885fb766e999fe9a479c9c0d306ca982e87e63906a7f6a01750a779` сохранён. Точные зарегистрированные байты portable adapter и прежнего verifier сохранены в [provenance](provenance/post-run-source-lineage.json); metadata отдельно закрепляет текущий исправленный adapter и текущий verifier. Научный recipe, признаки, граф, метки и результаты не изменены, повторных fit нет. Проверка допускает эту явную lineage только для guard и read-only verifier; изменение научных исходников или входов по-прежнему приводит к отказу.

Целевая механическая проверка обработки исторических пинов, без файлов, GPU-вызовов и fit: `python -B -m scripts.verify_seed_stability --check-pin-handling`. Она проверяет принятие неизменного пина и двух явно оформленных ревизий, а также отказ при необъяснённом drift, неверных historical/current SHA и попытке обойти scientific source/input pin.

Полный явный повтор оптимизации в **новый** каталог:

```console
python -B -m scripts.competition_seed_stability --execute --output reports/competition-enhancement/seed-stability-rerun
```

Скрипт запрещает перезапись/возобновление и повторяет правило остановки после timing-seed. Проверка такого каталога: `python -B -m scripts.verify_seed_stability --artifact reports/competition-enhancement/seed-stability-rerun`. Производственные выходы не перезаписываются. Версии выполненного расчёта: Python 3.10.1, NumPy 2.2.6, pandas 2.2.3, SciPy 1.14.1, scikit-learn 1.5.2, psutil 6.1.0, threadpoolctl 3.5.0; Windows — исходный guard, Linux/macOS — существующий явно частичный portable adapter.

## Применимость и исключённые варианты

Таблица отвечает на узкий вопрос: воспроизводится ли метка данного МО при новых случайных стартах **того же** оптимизатора. Её можно использовать как отдельное поле поддержки при описании типологии. В этих 20 повторах различий между МО по этому полю не обнаружено.

Не применялись другое представление признаков, упрощённый KMeans без joint, новая сетка K/alpha/графов, подбор удачных seed, семантическое переименование групп в каждом запуске, bootstrap данных или новый прогноз. Это сохранило предмет проверки и производственную модель. Вывод «тип экономически достоверен на 100%» отвергнут: выполненный эксперимент его не проверяет.
