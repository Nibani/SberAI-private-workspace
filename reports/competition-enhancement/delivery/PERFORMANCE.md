## Минимальное следующее ускорение

В `Dockerfile` `ARG SOURCE_REVISION` и `ENV SOURCE_REVISION=${SOURCE_REVISION}` расположены до apt и pip. После подключения обычного кеша слоёв перемена SHA будет инвалидировать дорогие слои даже при неизменных зависимостях. Предлагается перенести эти две строки ниже установки зависимостей, непосредственно перед `COPY . .`, затем использовать штатный BuildKit cache в CI. Приложение получит тот же SOURCE_REVISION; научные вычисления, версии пакетов и проверки не меняются. Это проверенная причина потери повторного использования слоёв, но улучшение времени ещё не измерено. Одно перемещение строк без сохранения Docker cache между runners не гарантирует ускорение GitHub Actions. Dockerfile в этой версии сохранён.

Для C достаточно сохранить уже выполненное ускорение декодирования и исходного кэша, а требование скорости описать честно. Удаление неиспользуемых PNG уменьшает комплект на 0,51%, но не первую загрузку. Разделение основного и архивного payload потенциально сильнее, однако меняет сложный маршрут offline-просмотра и требует отдельной проверки всех функций; для раннего C не предлагается.

## Парный сценарий

До измерений фиксируются два неизменных снимка, SHA HTML, каждого файла данных, исходников и зависимостей. Node: одинаковый распакованный JSON, одинаковая версия Node, один поток и BelowNormal; один прогрев, не менее шести пар AB и BA, SHA и DeepEqual после каждого вызова. Время чтения, base64, gzip и JSON.parse измеряются отдельно. Этим доказывается только работа с данными, без обещания времени карты.

Браузер: только уже разрешённый опубликованный HTTPS-сайт или разрешённый CI. Одинаковые Chromium, runner, viewport 1440×900 и 390×844, одна и та же последовательность: открытие, карта, поиск фиксированного МО, выбор, аналоги, исключение категории, смена месяца, годовое сравнение, архив. Отдельно выполнить холодный и тёплый кэш, чередовать порядок снимков и сохранить все повторы. Записывать request bytes, TTFB, получение HTML и payload, декодирование, JSON.parse, построение DOM и первый кадр карты. Проверить численные ответы и доступность функций после каждого опыта. Если нельзя открыть оба снимка в разрешённой среде, сравнение браузера остаётся UNVERIFIED. Запрет локального браузера соблюдён.

CI: один runner image, одинаковые входы и commands, одинаковый cache state; отдельные пары холодного и тёплого source cache и Docker cache. Сравнить download-and-verify, подготовку, сборку, тесты, контейнер и полный wall time. Не смешивать ускорение сети с ускорением модели. Несколько повторов нужны из-за разной нагрузки GitHub runners. Результат считать подтверждённым только для указанной пары и среды.
