# Первое сравнение: январь, июнь и декабрь 2023 года

Я сравнил KMeans, Ward и статический Leiden на 2 016 территориях. Во всех случаях использовались одни и те же пять признаков, масштабирование по 2023 году и сеть 15 ближайших соседей. Seed — 1729. Для KMeans и Ward задано 8 групп, для Leiden — resolution = 1.

| Месяц | KMeans: силуэт / групп | Ward: силуэт / групп | Leiden: силуэт / групп |
|---|---:|---:|---:|
| Январь | 0,212 / 8 | 0,157 / 8 | 0,118 / 13 |
| Июнь | 0,216 / 8 | 0,143 / 8 | 0,116 / 13 |
| Декабрь | 0,213 / 8 | 0,140 / 8 | 0,136 / 11 |

KMeans имеет более высокий силуэт на всех трёх месяцах. Это даёт основание оставить его сильным базовым вариантом. Однако число групп у Leiden отличается, проверена только одна настройка и один seed. По AVU лучше оказался Ward. Окончательный выбор метода по этим результатам делать рано.

Разделение групп пока умеренное. Эти числа сами по себе не подтверждают существование отдельных экономических типов и не дают названий вроде «промышленный» или «туристический».

## Метрики и ограничения

В `metrics.json` сохранены все значения, в том числе размеры групп и статусы неопределённых метрик. S_Dbw определён только для KMeans в июне и Ward в декабре; в остальных случаях возник нулевой знаменатель плотности. Такие значения оставлены `null`, а не заменены благоприятным числом. Формулу MQ ещё нужно уточнить.

В `partitions.csv` — 18 144 назначения: 2 016 территорий × 3 месяца × 3 метода. Поле `entity_id` соответствует исходному коду территории. Таблица не содержит экономических названий кластеров.

Расчёт по январю и июню не означает помесячного отслеживания переходов: промежуточные месяцы в этом эксперименте не использовались. Данные 2024 года пока не участвовали в сравнении методов.

## Воспроизведение

Конфигурации: `configs/pilot_bounded.json` и `configs/development_check_bounded.json`. Команды из корня проекта:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-models.txt -r requirements-monitor.txt
.\.venv\Scripts\python.exe scripts/run_bounded.py --config configs/pilot_bounded.json
.\.venv\Scripts\python.exe scripts/run_bounded.py --config configs/development_check_bounded.json
```

Полный декабрьский запуск, включая загрузку Python и паузы, занял 38,7 секунды. Дополнительный запуск по январю и июню — 11,1 секунды; библиотеки и файлы к этому моменту уже находились в кеше. Числа нельзя линейно переносить на большую программу сравнения.

Процесс ограничен 20% CPU и 1 ГиБ частной выделенной памяти, GPU не используется. В двух успешных запусках максимальные измеренные значения общей нагрузки: CPU — 5%, RAM — 59,5%, активность диска — 36,1%, GPU — 5%, видеопамять — 19,4%. До этого две попытки остановились при загрузке Python из-за активности диска выше 70%; затем введены короткие паузы. Мониторинг не исключает всплесков между замерами.

Хеши и параметры расчёта сохранены в `provenance.json`, нагрузка — в `resources_summary.json`, контрольные суммы файлов — в `SHA256.json`. Поле `git_commit` содержит базовый коммит: расчёт выполнялся с ещё не закоммиченными изменениями. Поэтому точную реализацию следует проверять по хешам модулей, а не только по этому коммиту. Все хеши модулей совпали с публикуемыми файлами. В `implementation_snapshot.json` отдельно сохранён снимок кода после расчётов, включая хеш скрипта ограничителя; хеш этого скрипта не фиксировался самим запуском.
