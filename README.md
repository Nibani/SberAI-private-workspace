# Экономические соседи

Мой проект для номинации «Кластеризация» конкурса СберИндекса.

Я исследую, какие муниципалитеты похожи по структуре потребительских расходов и насколько это сходство сохраняется со временем. Хочу получить понятный способ сравнивать территории: выбрать муниципалитет, найти его экономических соседей и увидеть, чем они похожи и чем отличаются.

## Что уже есть

- Данные СберИндекса за 2023–2024 годы: пять категорий расходов и общий итог.
- Набор из **2 016 территорий с полной историей за 24 месяца**. Ещё 174 территории имеют неполные ряды и учтены отдельно.
- Сеть сходства для каждого месяца.
- Код для сравнения KMeans, Ward и Leiden, расчёта метрик и анализа переходов.
- Локальный атлас с графиками расходов и списком похожих территорий.

Первое сравнение проведено на январе, июне и декабре 2023 года. KMeans дал силуэт 0,212–0,216, Ward — 0,140–0,157, Leiden — 0,116–0,136. Это предварительные результаты одной настройки; устойчивость и экономический смысл групп ещё предстоит проверить. [Результаты и файлы расчёта](reports/experiments/2026-09-23/README.md).

## Как устроен подход

В основе — соотношения расходов по категориям и общего итога. Так можно сравнивать потребительские профили, не сводя всё к делению на территории с высокими и низкими расходами.

В каждом месяце я соединяю похожие территории в сеть и сравниваю сетевую кластеризацию с обычными методами. Затем проверю, насколько результат зависит от настроек и подтверждается ли внешними экономическими показателями.

Ребро сети показывает сходство расходов. Оно не означает реальные поездки или денежные переводы между территориями.

## Запуск подготовки

Нужны Python 3.10 и PowerShell. Из папки проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\scripts\download_sources.ps1
.\.venv\Scripts\python.exe scripts/prepare.py
.\.venv\Scripts\python.exe scripts/prepare_graphs.py
.\.venv\Scripts\python.exe scripts/build_dashboard.py
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

После этого откройте `web/index.html` в браузере. Страница работает без сервера. Сырые данные загружаются из официальных источников и проверяются по SHA-256; в репозитории их нет.

Подготовка не запускает кластеризацию. Для отдельного запуска нужны зависимости из `requirements-models.txt`, параметр `execution.allow_clustering=true` в копии конфигурации и флаг `--execute-clustering`. Порядок сравнения описан в [плане экспериментов](docs/EXPERIMENT_PLAN.md).
