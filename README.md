Исследовательский проект Андрея для номинации «Кластеризация». Цель — первое место; текущая поставка — проверенные данные, готовый вычислительный конвейер и интерактивный прототип. **Обучение и кластеризация не запускались по указанию автора. Результатов сравнения моделей и подтверждённых экономических типов ещё нет.**

- Получен официальный набор с кодами территорий: **303 126 наблюдений, 2 190 territory_id, 24 месяца, 5 категорий и общий итог**.
- Его полное мультимножество чисел совпало с исходной CSV; устранена потеря идентификаторов при выгрузке. В CSV 49 неоднозначных названий.

- Подготовлен локальный интерактивный атлас: `web/index.html`.

## Быстрый запуск подготовки

PowerShell, из этой папки:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\scripts\download_sources.ps1
.\.venv\Scripts\python.exe scripts/prepare.py
.\.venv\Scripts\python.exe scripts/prepare_graphs.py
.\.venv\Scripts\python.exe scripts/build_dashboard.py
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m sbercluster.cli plan
```

В текущей локальной поставке данные уже скачаны; `scripts/download_sources.ps1` получает опубликованные архивы с проверкой зафиксированных SHA-256. Для дополнительной сверки можно положить исходный CSV из пользовательского ZIP в `data/raw/`; `scripts/import_csv.py <путь-к-zip>` распакует его безопасно. Без CSV подготовка работает напрямую из официального Parquet; проверка соответствия CSV тогда явно пропускается. Сырые файлы исключены из Git; см. [источники и лицензии](docs/DATA_SOURCES.md). На этой машине .venv использует установленные core-пакеты через `--system-site-packages`; чистый запуск выше требует установки всего requirements.txt.

Страница работает локально без сервера и CDN. Для будущей публикации нужно отдельно проверить права на производные поля справочника.

## Позднейший запуск моделей — только по новому поручению Андрея

Установить `requirements-models.txt`, сохранить копию `configs/pilot.json`, включить в ней `execution.allow_clustering=true` и передать `--execute-clustering`. Ни одна команда подготовки это не делает. Основной pilot — три статических метода. `configs/temporal.json` дополнительно требует документированной проверки границ. Для первого запуска использовать один срез и малый контроль согласно протоколу; не запускать всю сетку параметров.

Результаты каждого разрешённого запуска будут в `runs/<timestamp>/`: точная конфигурация, хеши кода и данных, признаки, графы с порядком узлов, разбиения, метрики и таблицы переходов. MQ остаётся явно неопределённой до ответа организаторов.
