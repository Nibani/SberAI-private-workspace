# Проверка и воспроизведение

После установки Python 3.10 и Node.js 22 или новее подготовьте среду один раз:

```sh
python -m pip install --require-hashes --only-binary=:all: -r requirements-jury.lock
npm ci --prefix tools/browser
node tools/browser/node_modules/playwright/cli.js install chromium
```

На Linux установка Chromium может потребовать системные библиотеки: используйте `install --with-deps chromium`. Для установки зависимостей нужен интернет. Просмотр уже включённого атласа через `docs/index.html` работает без него.

Основная команда:

```sh
python -B -X utf8 run_all.py
```

Она проверяет исторический ZIP, все 132 исходных научных SHA, сохранённые научные результаты, 73 исключения региона, добавочную ценность групп, арифметику 500 повторов выбора метода, синтетические результаты и 20 стартов оптимизации. Затем запускает проверку текущих зарегистрированных опытов, две точные пересборки и настоящий Chromium на localhost и холодном `file://` пакете. Старые пути восстанавливаются автоматически в отдельной рабочей копии; исходные отчёты не перезаписываются. Журнал, JSON с результатами этапов и браузерные материалы находятся в новом каталоге `artifacts/run-all/`.

Код 0 означает, что все обязательные этапы завершены. Ошибка даёт код 1. Быстрый режим `python run_all.py --quick`, отсутствующий браузер или ещё не поставленный текущий научный проверяющий модуль дают статус `UNVERIFIED` и ненулевой код. Пропущенный unit-тест также не считается полной приёмкой. Готовность научного опыта не означает, что его результат положителен: отрицательный результат проходит проверку, если он правильно получен и сохранён.

Область воспроизведения ограничена. Основная команда проверяет сохранённые синтетические строки и интервалы, но не повторяет весь синтетический training. Выбор метода проверяется по сохранённым 500 draws, без нового обучения десяти разбиений и пересчёта ICVI. Пересборка берёт замороженный `data/atlas-base.json.gz`, неизменные исторические таблицы, текущие результаты и шаблоны; это не восстановление данных из внешних архивов. 2024 уже использовался в историческом выборе архитектуры и не становится независимым прогнозом будущего. Chromium эмулирует размеры экранов и не удостоверяет физическое мобильное устройство.

Для отдельного полного исторического расчёта сначала подготовьте рабочую копию через основную команду. Её путь записан как `runtime_copy.root` в `summary.json`. Из этой копии можно запустить:

```sh
python -m scripts.run_v12 --config configs/v12.json --output runs/historical-refit
python -m scripts.check_method_ties --check
python -m scripts.reproduce_synthetic --output runs/synthetic-refit
```

Это отдельные длительные расчёты. Их результат и время не включаются в статус основной команды.

Полные исторические материалы и точные пути перечислены в [указателе свидетельств](evidence-index.md). Чтобы только распаковать исходные отчёты в отдельное место:

```sh
python -m scripts.logical_storage --materialize artifacts/legacy-evidence
```

`requirements-jury.lock` фиксирует прямые и транзитивные версии и хеши пакетов; `tools/browser/package-lock.json` фиксирует Playwright 1.62.1. Выполнение записывает путь и SHA браузера. CI использует ту же основную команду. Dockerfile предоставляет тот же вход, но успешный локальный Python/Chromium запуск не означает, что Docker-образ или удалённый CI уже проверены.

Для отдельной проверки сохранённого временного опыта:

```sh
python -B -X utf8 -m scripts.verify_current_results --only temporal
```

Если подробные checkpoint-файлы упакованы в дополнительный архив, команда проверяет его точный состав, CRC и SHA, создаёт отдельную рабочую копию с прежними путями и запускает из неё исходный verifier. Ни его код, ни registration не меняются. Код 0 означает корректность сохранённых результатов; отрицательный научный gate остаётся отрицательным и не превращается в допуск метода. Без `--only` wrapper требует обе текущие научные проверки.

Команда `python -m scripts.verify_temporal_changes` в закреплённом [описании опыта](TEMPORAL_CHANGES.md) сохраняет исходную проверку опыта, включая точное равенство вычисленных дробных чисел; её код оставлен неизменным. Для текущей поставки используйте команду выше: она вызывает переносимый проверяющий модуль, сохраняет все исходные SHA, целочисленные результаты и научные пороги, а вычисленные дробные сводки сравнивает с абсолютным и относительным допуском 10⁻¹². Каждое отличие печатается с точными значениями; допуск не меняет условия научного успеха. Сводки, кривые и реальные проекции доступны обычными файлами; подробные данные не требуют постоянной распаковки в source.

Для Docker предусмотрена та же команда:

```sh
docker build --build-arg SOURCE_REVISION=YOUR_COMMIT -t sber-atlas-check .
docker run --rm sber-atlas-check
```

Вместо `YOUR_COMMIT` укажите SHA исходного снимка. Python- и Node-образы указаны конкретными версиями. Их разрешённые digests нужно записать при сборке релиза; сама сборка в текущей подготовке не выполнялась.
